# Desktop UI and background operations

## Ownership and flow

- [src/gui/mod.rs](../../src/gui/mod.rs) owns the application shell, profile selector, startup recovery and footer. [mod_list.rs](../../src/gui/mod_list.rs) renders rows, [sorting.rs](../../src/gui/sorting.rs) owns display comparators, [settings.rs](../../src/gui/settings.rs) owns Settings/provider dialogs, and [lint.rs](../../src/gui/lint.rs) owns lint selection/reports.
- [src/gui/message.rs](../../src/gui/message.rs) dispatches asynchronous provider/download/integration operations and receives results. [RequestCounter](../../src/gui/request_counter.rs) identifies requests; matching IDs prevent stale results from applying to a newer operation.
- [src/gui/icons.rs](../../src/gui/icons.rs) owns icon controls and display-scale-aware SVG texture reuse. [named_combobox.rs](../../src/gui/named_combobox.rs) owns profile/group selection controls.
- [diagnostics.rs](../../src/gui/diagnostics.rs) formats error chains, redacts provider secrets and renders selectable/copyable details. The footer keeps a short status and opens a separate details window without changing row geometry.
- [notifications.rs](../../src/gui/notifications.rs) owns dismissible bottom-center snackbars above the footer. Success messages last ten seconds with a filling progress strip, followed by a short fade. Hovering anywhere over the snackbar pauses its timer; leaving resumes the remaining time. The 24-pixel status and close icons are centered against the whole card; the close target is 32 pixels. Repeated identical messages renew one notification. Pending successes are bounded; errors take priority, remain until dismissed and retain their own redacted details even after later operations. Existing background-operation statuses are presented once. Editing successes are enqueued only after saving; cancelled, unchanged, moved, reordered and toggled entries stay silent. Profile and mod-link copies report their scope, excluding disabled mods and groups; an empty active selection leaves the clipboard unchanged.
- [src/state/mod.rs](../../src/state/mod.rs) owns durable settings and profile data. Render code consumes those owners rather than maintaining a second persisted representation.

Keep network and blocking integration outside the egui frame. When changing cancellation, profile switching, or result handling, inspect both dispatch and receive paths, including stale completion, failure, and progress updates. Preserve resolved mod/load ordering across asynchronous work.

Settings exposes Show notifications, enabled by default and saved immediately. When disabled, the notification owner clears visible and queued snackbars, including errors, and consumes background statuses without presenting them later. Re-enabling shows only new notifications. Footer status, manually opened details, confirmation dialogs and toolbar Undo/Redo remain available.

## Profile and group editing

[history.rs](../../src/gui/history.rs) owns a shared, in-memory undo/redo history of at most 50 profile/mod-data changes. Every GUI mod-data save goes through `save_mod_data`, including imports, profile edits, shared-group operations, mod versions, priorities and toggles. Snapshots share adjacent states and cover all profiles and groups together; profile selection alone does not create an edit. Sorting, expansion, settings, copying and game/cache operations are outside this history. A drag's switch to Manual remains a view setting when undoing the saved list order. New content edits discard redo; restarting starts with empty history. Unsaved edits remain tracked in memory, but emit no success notification. Failed undo/redo saves restore the prior in-memory state and leave the cursor unchanged for retry. Unknown content changes are rejected rather than overwritten.

The compact profile toolbar exposes Undo/Redo; Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z apply only outside focused text editing, confirmations, dragging and conflicting background operations. A snackbar Undo carries its own history ID and is enabled only when that exact edit is next to undo; it never silently undoes newer work. Dismissing or expiring notifications does not discard history. Successful Undo/Redo emits no snackbar and dismisses notifications for the restored edit; failures still show error details. Restoring keeps the current profile when it still exists, otherwise selects an available restored profile. Shared-group references and members are restored together; no game or downloaded files are changed.

The contiguous group section precedes standalone mods. Dragging a mod outside a group clamps insertion to the standalone section; dragging a group clamps to the group section. The drop preview opens space at the clamped destination, including drops beside or below groups, while dropping on a group header still adds a member. Ungroup appends members to the end of the standalone section. Older layouts with groups after standalone mods show an Arrange groups notice and cannot be dragged until explicitly arranged. The confirmation warns about load order, opens without a focused button and cannot be bypassed with Shift. Create/attach/move/ungroup requests on such a profile open this confirmation first; the user retries the intended operation afterward. Cancellation and stale confirmation leave the order unchanged. Other profile data and shared group contents are not rearranged.

[editing.rs](../../src/gui/editing.rs) owns deletion confirmation and delegates to [state/edits.rs](../../src/state/edits.rs). Normal mod, duplicate, group-reference, shared-group and profile deletion requires confirmation. Shift at the originating click bypasses the dialog; neither button initially has focus, Enter alone does nothing, Tab enables explicit keyboard selection and Escape cancels. A prepared deletion captures the profile data and refuses to run if that data changed while the dialog was open. Never reinterpret a saved display index against a newly sorted or changed list.

[groups.rs](../../src/gui/groups.rs) exposes shared-group creation, attachment, renaming, membership and global deletion through the Groups button. Mod-name context menus move entries into/out of groups; group-header menus expose rename and ungroup. Row deletion detaches a group from one profile, while the manager's Delete group removes it globally with explicit affected-profile text. Display the sharing semantics; do not silently turn shared groups into profile-local copies. Ungroup is an explicit copy into the current profile, preserving order and effective enabled states, and leaves the shared definition available to other profiles.

The Groups window leads with name entry and creation; advanced shared-group operations are collapsed by default. [drag_drop.rs](../../src/gui/drag_drop.rs) handles moves between the profile and groups, group-member ordering and profile ordering in every sorting mode. Root and group-child rows share the same drag path. Group headers accept mods, the drop preview shows exact positions, and the drag hint identifies shared targets. While dragging, each row records the range of shapes it painted (`RowPaint`). After all rows are laid out, the preview moves the dragged row's shapes to a foreground layer that follows the pointer, and slides the other rows' shapes by animated offsets so that space opens at the insertion point. Group backgrounds, member backgrounds and gutters stretch with their members. Only painted shapes move: the layout and hit testing keep the rows' real positions. Drop targets follow what is on screen: the lifted row's top edge is mapped back to the layout (positions below the lifted slot move down by its height) and picks the target, so the opened space always lies under at least half of the lifted row in both directions. Because the mapping uses only the unchanged layout, the preview cannot feed back into target selection. Hovering a collapsed group opens it when that same drop point is over the group. Appending to a collapsed group only highlights its header. Animation state is keyed by a per-drag ID, so a release, cancellation or new drag never animates back from an earlier preview. Apply only on release over a valid target against captured data, display order and sorting mode. A changed drop materializes the active profile's displayed order and all its referenced shared-group member orders, applies the move atomically, then switches to Manual. Groups not referenced by that profile retain their order; shared groups still affect every referring profile. Escape, external drops, stale snapshots and no-op drops preserve data and sorting. Row scopes and switch IDs follow entry identity rather than visual position so reordering does not inherit another mod's switch animation; groups cannot nest.

The UI disables editing while conflicting background work or a confirmation is active. Group mutations are validated atomically in memory before using the existing save path; a save failure remains visible and retains the in-memory change for recovery. No deletion here removes a mod file or cache blob. Mod removal uses the title "Remove mod?" and the "Remove" action. Center the confirmation title and actions with clear spacing while keeping the surrounding list compact. Dropdowns and name-entry popups close on outside presses as well as Escape.

## Windows startup and diagnostics

### Application updates

[app_update.rs](../../src/app_update.rs) owns the application download, staging, archive validation and executable replacement; [gui/app_update.rs](../../src/gui/app_update.rs) owns its modal UI. This is separate from mod metadata checks. Downloads use the displayed release tag, write all bytes, flush/sync and close the archive before extracting the platform executable. Staging lives beside the application. Non-Windows replacement uses the existing `self_update` dependency's `self_replace` support and retains a recovery copy.

[app_update/windows.rs](../../src/app_update/windows.rs) stages the new Windows executable and moves the old image into a unique adjacent directory. It checks cleanup readiness before moving the running image, retries sharing violations for up to ten seconds, and restores the old executable if installation or the cleanup commit fails. Failed restoration preserves the recovery directory and reports its location. The embedded [cleanup script](../../src/app_update/cleanup.ps1) runs through system Windows PowerShell without profiles, a console window, or execution-policy changes. Paths travel through environment variables, never interpolated shell commands. Cleanup waits for the original process to exit and removes only that update's previous executable, commit marker and empty directory; it creates no temporary helper executable. A missing commit marker preserves interrupted-update recovery files. Transient cleanup locks retry for up to one minute; persistent failures retain a local diagnostic. Do not scan or delete arbitrary legacy `.mint.*.exe` files on startup.

Cancellation and the start of replacement use one atomic gate: a cancelled operation cannot begin replacement, and replacement cannot be interrupted by the Cancel button. Window close requests wait for the active worker to cancel or finish. Restart preserves startup arguments, including `--appdata`, saves settings before launching the new process, and closes the old window normally; a launch failure remains visible instead of panicking.

The release dialog bounds its width/height to the viewport, scrolls the notes separately and keeps actions visible. Its heading shows the available and current versions. X, Escape and Remind me later dismiss immediately before installation. While an update runs, Escape and clicks outside are ignored; X becomes Cancel update and, like Cancel, only requests cancellation, so the dialog stays open to show the result. After a failure the install action reads Retry; while other mod work is running it is disabled with an explanation. Dismissal suppresses automatic reopening for that session. Settings shows the current version, manual Check for updates, check results and View update. Checks distinguish current, available, invalid-response and failed states; stale request results cannot replace newer state. A completed update allows Later and remains reopenable for Restart now.

Regression tests cover full/truncated/failed downloads, invalid archives, cancellation, a running child executable's replacement and recovery, small-window action visibility, dismissal and manual reopening, accidental dismissal during a running update, and the version heading/Retry label. The opt-in `gui::tests::app_update::native_update_preview` fixture runs only when `MINT_NATIVE_UPDATE_PREVIEW` names a disposable data directory. Copy the test executable into that directory before running it; the fixture enforces this location. Install update replaces that copy with the public release matching the Cargo version, or a local fixture archive supplied through the test-only `MINT_NATIVE_UPDATE_URL`. Never use personal data. Its native event loop uses the already-resolved `winit` crate as a development dependency only; production builds contain neither test entry point nor URL override.

### Startup and logging

The application icon's canonical source is [assets/brand/mint.svg](../../assets/brand/mint.svg), an original code-authored M monogram. The root build script renders a 256-pixel PNG for the root viewport and a multi-resolution ICO (16 through 256 pixels) for the Windows executable resource. Generated assets stay in Cargo's output directory and are embedded; no external icon files are needed at runtime. Child viewports inherit the root icon. Edit the SVG instead of maintaining independent PNG/ICO copies. Windows builds require a working resource compiler (the Windows SDK on MSVC or windres on GNU targets); missing tooling fails the build rather than silently shipping the default icon.

Group expansion belongs to [group_view.rs](../../src/gui/group_view.rs), separate from saved mod data. Newly created/attached groups and successful drop destinations open immediately. Hovering a mod over a closed group for 500 ms expands it temporarily; the entire visible group is the hover region. Leaving or cancelling restores the prior collapsed state, while a successful drop keeps it open. Already-open groups stay open.

Group headers show the total member count beside the name, including disabled mods. The name, arrow and remaining header width toggle expansion on left click and open the shared context menu on right click. This target excludes the separate drag, delete and enable controls and the member rows.

Use `icons::collapsing_header` for collapsible content sections (groups, notices, group management and lint reports) and `icons::combo_box` for selection dropdowns. Both reuse the cached `keyboard_arrow_right` SVG. Section arrows rotate continuously from right to down with egui's body expansion; dropdown arrows rotate from down to up while open. Keep widget IDs, compact geometry and existing interaction behavior stable.

[group_colors.rs](../../src/gui/group_colors.rs) owns the 15-color theme-aware palette and the 5-by-3 color-dot picker in the group-header context menu. A group's header and left indentation gutter share its color; member rows retain normal alternating backgrounds. The selected dot has a ring and checkmark, with named hover/focus support. Color is a saved property of the shared group, so every referring profile displays the same choice. Gray is the default for old groups. Apply palette changes through the validated edit/save path without changing row geometry or drag targets.

Text inputs use [inputs.rs](../../src/gui/inputs.rs) for a shared theme-aware border, preserving native focus indication and compact geometry. On Windows, [native_popup.rs](../../src/gui/native_popup.rs) dismisses popups on non-client mouse presses (including the title bar) and focus loss through a window subclass removed on destruction. Other platforms use egui focus/outside-press handling.

The live viewer formats each timestamp once as `[YYYY-MM-DD HH:MM:SS]` in UTC and labels the toolbar `Time: UTC`; raw log files retain their original format. Timestamp formatting runs in the asynchronous reader and preserves message bodies and continuation lines. The viewer defaults to INFO/WARN/ERROR; Show debug includes DEBUG/TRACE and their continuation lines. Unknown text is preserved. Cached display text wraps to the viewport width, WARN/ERROR use theme-aware text colors, and Copy visible log copies the filtered, redacted view. Filtering never removes entries from the file. Completed profile/group edits log readable operation sentences with the affected item and outcome after the save attempt. Cancelled and unchanged operations do not emit success events; rejected edits and unsaved in-memory changes are distinguished. Provider secrets are redacted before edit descriptions are logged.

The Windows executable uses the GUI subsystem, so Explorer launch does not allocate a console. [windows_startup.rs](../../src/windows_startup.rs) attaches to an existing parent console for CLI use and preserves redirected input/output/error handles. CLI help, errors, exit codes and output redirection must remain testable. The caller's terminal is never hidden or closed. Settings exposes Open log for the current `mint.log` and Live log for a separate native viewport owned by [log_window.rs](../../src/gui/log_window.rs). Its cancellable async worker refreshes the last 128 KiB every 500 ms and redacts configured provider secrets before display/copy. The viewer supports pause, follow and always-on-top; closing it stops the reader without exiting the main app. No file IO runs in the rendering callback. Existing selectable error details remain available.

Tracked background tasks report unexpected panics through their request ID; the panic message, location and backtrace are written to `mint.log` by the logging panic hook. Footer failures are also logged. [mint_lib::redaction](../../mint_lib/src/redaction.rs) filters all log output: provider parameter values registered by the mod store, credential parameters such as `token=`/`Bearer`, and the current user's name in paths. The log viewer's own redaction remains in place. Completion/failure clears only the matching operation; failed lint reports stop showing the running spinner. Closing a report window does not abandon an active worker. Integration cancellation retains its busy handle until the writer finishes; see the integration contract for staged replacement and locking.

Partial imports preserve input order and keep errors available for retry; they are not permission for installation to ignore failures. Search highlighting maps lowercase matches back to original UTF-8 character boundaries, including characters whose lowercase representation changes length.

### Dialogs and window state

Non-modal dialogs (Settings, provider configuration, Groups, Check mod files and its report, error/notification details, profile windows and the embedded Live log fallback) are created through `dialog()` in [mod.rs](../../src/gui/mod.rs): never collapsible, movable and resizable with a minimum size, constrained to the main window, with scrolling content and a default size clamped to the window. Confirmations remain `egui::Modal` prompts. The native Live log viewport is unchanged.

The Compact/Normal switch uses the shared `icons::segmented` inline select bar, also in Settings. Segments are focusable buttons with selected state, icon and text, sharing one border.

eframe's persistence feature restores the main window's size, position and maximized state from `window.ron` in the data directory, clamped to the connected monitors, so `--appdata` isolates it. egui memory, including dialog placement, is not persisted. The main window has a 480x320 minimum size.

## UI invariants

[updates.rs](../../src/gui/updates.rs) owns the two-row footer and structured refresh details. The upper row retains a colored operation badge, Details and a width-bounded message alongside installation status; the lower row owns actions. Notifications stay above both rows. Reports retain their own snapshot, list friendly mod names/reasons, disclose technical details separately, and retry only failed or unattempted mods. A cache-save retry can persist in-memory successes without another network request.

An empty profile shows a short hint for adding mods (Add mod or dropping .pak files). Without a configured game installation, the idle footer asks the user to select it in Settings instead of reporting Ready.

The footer's Install mods button uses the primary blue style while `InstallationStatus::needs_install` reports that the active profile differs from the installed record. Unknown, legacy or unreadable states never set it. The Normal view subtitle and details panel show that newest file date as Updated YYYY-MM-DD (UTC).

Check mod updates offers the current profile (including disabled entries) or all cached mod.io mods. Each mod.io row also offers Check for updates in its context menu, including missing-metadata rows. Checks never change pinned selections or install files. A newer cached version on a pinned row explains how to select latest; a known difference from the installed version directs the user to Install mods. Check mod files is the user-facing name for the existing lint engine; its dialog explains that checks may download files but do not install them or prove runtime compatibility.

[installation.rs](../../src/gui/installation.rs) compares the current profile's effective enabled load order with the installed record. Background probes read the pak and local file stamps, never in a UI frame. Results for changed requests are discarded. Probes pause during operations and refresh after completion; missing/unreadable/legacy records remain distinct from a matching installation. See the [integration contract](integration.md) for format and detection limits.

[fonts.rs](../../src/gui/fonts.rs) appends an embedded Noto Sans CJK font to the proportional and monospace fallback chains at GUI initialization, including startup recovery and the live log. Default Latin glyphs and compact control sizes remain unchanged. Font coverage is independent of installed OS fonts and network access. The bundled pan-CJK font uses Simplified Chinese forms for shared Han characters; it does not add script shaping or bidirectional layout support to egui. Keep its pinned provenance, license in Settings and release-archive notice together. Unicode glyph, input/IME-event, search, highlighting and persistence regressions live in [unicode_text.rs](../../src/gui/tests/unicode_text.rs).

Search validity and highlighted matches use the same Unicode-aware matcher in [find_string.rs](../../src/gui/find_string.rs), addressing the displayed mod name or the specification URL when metadata is unavailable. Case conversion must map highlights back to original UTF-8 boundaries; never slice original text with offsets into a transformed string. Search remains substring-based and does not promise transliteration or canonical-normalization equivalence.

### Mod list views, details and filters

The mod list has two views, chosen beside Sort by and in Settings: Compact (the default, with the historical row geometry) and Normal. Normal mod rows are 40 logical pixels tall, center their controls vertically and stack the name over tags, author and summary. Group headers keep the compact height. Both views keep the same control order, row identity, stored-index actions and drag paths. View choices are presentation settings in `config.json` (`ModListSettings`), saved immediately, outside mod data and undo history.

[thumbnails.rs](../../src/gui/thumbnails.rs) owns row and details-panel images. Provider details expose only cached URLs. Rows request a texture only when thumbnails are enabled for the current view and the row is visible. Loading runs on the Tokio runtime with at most four parallel loads: it reads `cache/thumbnails/<sha256(url)>` or downloads over `https` without provider credentials, rejects responses over 4 MiB, validates the image before caching it atomically and decodes it to 128x72 (rows) or 320x180 (details). Decoding always runs on a blocking thread and rejects images over 4096 pixels per side or 64 MiB of decoder memory, so a small file claiming huge dimensions cannot exhaust memory. An unreadable cached file is deleted and downloaded again. Failed loads show the placeholder until restart and are not retried every frame. Large textures are kept in a small LRU. Startup trims the disk cache to 64 MiB, oldest first. With downloading disabled no thumbnail request is made and rows show deterministic placeholders. Missing metadata uses the same placeholders.

Clicking a mod thumbnail or the free space of a mod row selects it for the right-side details panel ([details.rs](../../src/gui/details.rs)). Clicking or middle-clicking the mod name opens the mod page, as before the panel existed, and its context menu offers Show details. The panel has a header (wrapping name, author and source, close button), the thumbnail, an action row (primary Open mod page, Copy link, and a Check for updates icon for mod.io mods), the summary, then sections with small uppercase titles: an outlined Overview card (status with a colored dot, group, version with a pinned badge, updated date and the priority editor), Tags drawn with the list's tag chips (`modio_tags`, `tag_chip`) plus game versions, Dependencies, and collapsible Versions with latest and selected badges. The panel takes 240 to 560 pixels but at most 45% of the window, so narrow windows keep room for the list. Outside a drag of its edge it returns to the saved width whenever the window has room, and only widths set by dragging the edge are saved. Its scrolling content has a fixed width, the panel width minus a constant gutter for the floating scroll bar (`content_width`), so showing or hiding the bar never changes wrapping or the image size. A bar-dependent width would feed back into the content height and make the panel flicker between two layouts at some sizes. A dragged width is written once, after the pointer is released. Each mod row registers a click target (`reserve_row`) before its controls and updates it to the row's current slot after drawing. egui keeps a widget's hit-test order when it is updated later in the frame, so the target stays below the row's controls: toggles, dropdowns, buttons and the name keep their own clicks, a left click on free space selects the row, and a right click anywhere on the row opens the same mod menu as the name. Like other click targets the row is focusable: it is labeled "<name> details" for screen readers, the focused row gets the selection outline, and Enter or Space shows its details. That menu offers Hide details instead of Show details for the selected row, and labels the group move Move to shared group, explaining sharing in its tooltip. Never register a row target with a rectangle from an earlier frame, which can cover other rows' controls while the layout changes. A row's slot (`row_slot`) adds half of the row spacing above and below it, so adjacent slots meet: stripes, the hover color, the selection and row clicks all use it and leave no dead gap between rows. The selected row is filled with `row_selected_fill`, a stronger tint of the same selection color as the hover fill, and outlined with the selection stroke. The outline is painted after every row so the next row's background cannot cover its lower edge, and it is hidden while dragging because only row shapes move with the preview. Row lines on the outline's top or bottom edge are removed while it is shown, so the selected row's edges keep one even width. Escape clears the selection unless a focused control, an open dropdown, a delete confirmation, another modal or a drag uses it. egui removes focus on Escape before the panel runs, so the list records the focused control at the end of each frame (`remember_focus`) and Escape in the search box only clears the search. egui consumes Escape to cancel drags. With a mod selected, Up and Down step the selection through the shown mods in display order (`arrow_step`): sorting, filters and search apply, members of expanded groups are included, and the selection stops at the ends. The keys act when nothing has focus or a mod row has it, and focus then follows the selection, because focused rows claim vertical arrows from egui's focus navigation. Other focused controls keep the keys for that navigation. The list scrolls to the new row. The selection stores the list target and URL, follows the entry when its stored index moves and closes when it is removed or its profile is no longer shown. The panel reads cached metadata and versions only. Its priority editor uses the normal save path and history, and it is disabled with the list during conflicting work.

Rows show the load priority editor by default, including zero, as before. Settings can hide it from rows so it is edited in the details panel. The unreleased `non_zero` setting value reads as Always. Row tags can be hidden.

Row tags remain disabled small egui buttons: approval and required-status tags keep their colored fill, neutral tags (Optional and categories) use a transparent fill with an outline and the theme's strong text color (`neutral_tag_text`), because disabled widgets fade halfway to the background and gray text became unreadable on strong stripes, and tags are 4 pixels apart. In compact rows, tags are laid out from the right first and the mod name takes the remaining width, truncating with an ellipsis. Tags are dropped in reverse importance (categories, then required status, then approval) when fewer than 160 logical pixels would remain for the name. Normal rows apply the same rule to the tag and subtitle line. Every other mod row uses the Row striping setting: Off, Subtle (the theme's faint background, as before), Medium (default) or Strong, mixed from the panel and text colors with a larger share in dark themes. The separate Row lines setting draws a 1-pixel line in the noninteractive stroke color above every row except the first, centered in the row spacing, and works with any striping level. Lines are painted within each row's shapes, so the drag preview moves them with the row. While the details panel is open, the list leaves a 12-pixel gap so its scroll bar does not overlap the panel's resize handle. The list's scroll area fills the remaining space (`auto_shrink(false)`), so the space below the rows is a drop target for the end of the list. A list that shrinks to its rows collapses to zero height when a search or filter empties it while its fading scroll bar can still be dragged, which makes egui divide by zero.

[filters.rs](../../src/gui/filters.rs) owns session-only filter chips with per-chip counts. Chips within a category combine with OR and categories with AND: state (effective enabled state, including a disabled group), status (pinned mod.io mod with a newer cached version, missing metadata) and provider (resolved from metadata or the URL). Filtering hides rows only. Groups stay visible when any member matches and show matching/total counts. Dragging is disabled while a filter is active, while drag snapshots keep the complete display order. The search box is applied in the same `filter_order` step: a mod matches when its name (its URL without metadata) or one of its tags contains the text, ignoring case, and a group whose name matches keeps all members that pass the chips. Matches stay highlighted. While searching, groups with shown members are drawn expanded without changing their saved expansion. A header click during a search collapses or expands the group only until the search is cleared, and the empty-result notice offers to clear the search and chips.

List rows use one logical pixel of vertical inner padding above and below their controls, with no horizontal padding. The list disables egui's hover and press expansion so controls never reach into the neighboring row. Hover feedback is color only. The mod row under the pointer (standalone or group member, not group headers) gets `row_hover_fill`, a light tint of the theme's selection color that is distinct from every striping level. It is suppressed while dragging or while the list is disabled. Stripe and hover backgrounds are painted into a placeholder behind the row so the frame does not cover them. They extend into half of the row spacing above and below, so adjacent mod rows meet without a gap, while group headers keep their separate rounded bars. Apply the same padding to standalone rows, group headers and group members; keep control sizes unchanged.

The compact row geometry and existing control placement are intentional. The Normal view is the only taller row layout. A visual correction does not authorize a layout redesign, larger rows, or a table header. Reuse the icon/control owner before adding another implementation. In both themes, add buttons are blue with white icons; delete icons and confirmation actions are red with white foregrounds. Hover and pressed states use darker fills. Preserve disabled styling, theme selection, focus and keyboard behavior.

Sorting derives display indices without rewriting manual order. Group boundaries stay in place; individual runs and group children are sorted independently. Row actions must address stored entries, not sorted positions. Missing metadata is valid, including adjacent entries where one or both have none.

[sorting.rs](../../src/gui/sorting.rs) owns the compact Sort by dropdown and adjacent Ascending/Descending button. Manual disables direction changes and restores saved drag order. Category changes preserve the selected direction; starting from Manual uses the base comparison order. The historical `is_ascending` field actually reverses that base order, so the control maps it to Descending without changing the stored format or comparator. Selecting the current category does not flip direction. Last updated compares the upload time of the newest cached mod file (from provider details). Entries without a date come first in the base order and ties fall back to name order. Dropdowns retain outside-click and Escape dismissal.

## Test boundaries

[src/gui/tests.rs](../../src/gui/tests.rs) contains the existing `TestApp` harness, egui event injection, AccessKit/control lookup, sorting checks, and layout regressions. Extend it for behavior it can observe before introducing another UI test framework.

The harness's placeholder `.pak` files represent UI entries, not valid integration payloads. Use the real pak fixtures under [test_assets/lints](../../test_assets/lints) for the lint behavior they cover; do not equate either fixture set with an in-game integration test.

[GUI editing tests](../../src/gui/tests/editing.rs) cover confirmation, Shift, cancellation, stale targets and shared-group deletion. [State editing tests](../../src/state/edits/tests.rs) cover atomic failure, references, ordering and reload. [Windows startup tests](../../tests/windows_startup.rs) verify the executable subsystem and redirected CLI behavior. Test group menus and the native log-opening action in an isolated visible session as well.

For a visible preview, choose a task-owned `--appdata` directory outside the repository and inspect the selected game path before performing actions. A fresh config can auto-discover the installed game: separate app data does not isolate game writes. For a UI-only demo, set `drg_pak_path` to null in the disposable config and avoid Install, Uninstall, Launch, and self-update actions.

Check the affected controls in light/dark themes, hover/pressed/selected/disabled states, representative display scaling, small/resized windows, long names, empty/populated groups, and missing metadata. Capture actual application states only when useful evidence is needed. Record which checks were automated, manually exercised, or unavailable; native window behavior and injected game hooks are not proven by headless egui tests.
